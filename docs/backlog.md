## Backlog проекта: Интеллектуальный помощник диспетчера
### Задача 1: Описать схему полей заявки
**Владелец:** Бизнес-аналитик
**Результат:** Таблица полей (ID, тема, текст, подразделение, приоритет) с типами, обязательностью и источником данных.
**Приоритет:** Высокий
**Критерий готовности:** Другой участник может по документу сформировать валидный JSON-пример заявки.
**Категория:** Документы
**Задача 2:** Провести разведочный анализ данных (EDA)
**Владелец:** Инженер по данным / ML
**Результат:** Отчёт с описанием распределения классов приоритетов, объёма текстов, пропусков и качества разметки в 12 000 заявках.
**Приоритет:** Высокий
**Критерий готовности:** Команда понимает, какие классы несбалансированы и нужно ли дообучение/переразметка.
**Категория:** Данные
### Задача 3: Собрать базовую модель классификации приоритета
**Владелец:** Инженер по данным / ML
**Результат:** Обученная модель (например, TF-IDF + логистическая регрессия или трансформер), выдающая прогноз приоритета и confidence score.
**Приоритет:** Высокий
**Критерий готовности:** Модель работает на тестовой выборке из 2 000 заявок; метрики Macro F1 ≥ 0,72 и recall критических ≥ 0,80.
**Категория:** Модель
### Задача 4: Разработать API для получения рекомендации
Владелец: Разработчик / архитектор
Результат: REST-endpoint, принимающий текст и тему заявки, возвращающий JSON с рекомендуемым приоритетом, подразделением и уверенностью модели.
Приоритет: Средний
Критерий готовности: API отвечает не более чем за 2 секунды на одну заявку; конфигурация отделена от кода.
Категория: API
### Задача 5: Создать прототип интерфейса для диспетчера
Владелец: Разработчик / UI
Результат: Веб-страница или форма, где диспетчер видит текст заявки, рекомендацию модели с confidence score и кнопки «Подтвердить» / «Изменить».
Приоритет: Средний
Критерий готовности: Диспетчер может пройти полный сценарий: ввести заявку → получить рекомендацию → подтвердить/изменить → увидеть сохранённый результат.
Категория: UI
### Задача 6: Настроить логирование прогнозов и решений
Владелец: Разработчик / архитектор
Результат: Таблица/лог, куда сохраняются: ID заявки, прогноз модели, confidence, финальное решение диспетчера, timestamp.
Приоритет: Средний
Критерий готовности: После 10 обработанных заявок все поля корректно записаны и доступны для анализа.
Категория: Данные
### Задача 7: Провести тестирование на критических инцидентах
Владелец: QA / специалист по рискам
Результат: Отчёт о том, как модель справляется с заявками класса «критический»: сколько пропущено, сколько ложных срабатываний.
Приоритет: Высокий
Критерий готовности: Recall критических ≥ 0,80 на отложенной выборке; найдены и задокументированы типичные ошибки модели.
Категория: Тестирование
### Задача 8: Подготовить README и документацию проекта
Владелец: Менеджер проекта
Результат: README в репозитории с описанием цели, структуры проекта, инструкцией по запуску и ссылками на артефакты.
Приоритет: Низкий
Критерий готовности: Новый участник команды может по README понять цель проекта и запустить прототип.
Категория: Документы
